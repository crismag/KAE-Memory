# TASK-009 — M8 Semantic Retrieval

**Status:** complete, 2026-07-27
**Milestone:** M8

## Objective

Add semantic recall over durable knowledge, per ADR-0008.

## Delivered

- `KnowledgeChunk` domain contract with content hashing, embedding lifecycle
  (`pending`, `embedded`, `stale`, `failed`), and staleness detection against
  both text and embedding version.
- Chunking on semantic boundaries: short entities stay whole, long documents
  split on paragraphs then sentences, targeting 300–700 tokens.
- The metadata prefix (`Type`, `Project`, `Title`, `Status`) prepended to
  embedded text, so one index serves every knowledge kind.
- `EmbeddingPort` — separate from `ExtractionPort` — with a deterministic
  adapter and a Titan adapter over `boto3`.
- Revision `0004`: `knowledge_chunks` with `VECTOR(1024)` and a single
  `CREATE VECTOR INDEX`.
- `RetrievalService`: chunk, embed pending, search by cosine distance scoped to
  one project and one embedding version, each hit carrying an explanation.
- The evaluation fixture: 18 corpus items, 8 cases.

## Completion notes

**Written by hand, not autogenerated.** Alembic's autogenerate against
CockroachDB reported a page of cosmetic differences that are not real changes —
`INTEGER` versus `BigInteger`, `VARCHAR` versus `Text`, and `NULLS FIRST` in
reflected index expressions. Accepting them would have rewritten columns that are
already correct. Revision `0004` contains only the new table, its indexes, and
the raw `CREATE VECTOR INDEX` that Alembic has no operation for.

**The evaluation fixture proves less offline than ADR-0008 implies, and this is
stated rather than glossed.** The deterministic embedder is hash-derived and has
no notion of meaning. Against it the fixture verifies the *harness*: every query
runs, ranking is by ascending distance, top-k is respected, every hit explains
itself, and scoring works. Measured recall@8 is 50%, which is **chance** — top-8
of an 18-item corpus is ~44% by accident. The test prints the chance level next
to the result so the number is never mistaken for a quality signal.

Ranking quality needs the real model. The same fixture runs against Titan under
`KAE_EVAL_LIVE_EMBEDDING=1`, where a 75% recall threshold is enforced. That is a
live provider call and therefore opt-in, never in CI.

**Consequence for the milestone:** M8's code is complete and its pipeline is
verified end to end against real CockroachDB vectors, but ADR-0008's acceptance
criterion — the expected item appearing in top-k — is only genuinely tested by
the live run. That run has not happened and requires AWS credentials with Bedrock
access to `amazon.titan-embed-text-v2:0`.

**Deviations:** none. Revisions `0001`–`0003` untouched, one vector index on a
shared table, no reranking or hybrid search, no cross-project reads, no live call
in the suite.

**Evidence:** `make check` green — 112 tests, against CockroachDB v26.2.1 with a
real `VECTOR(1024)` column, cosine operator, and vector index.
