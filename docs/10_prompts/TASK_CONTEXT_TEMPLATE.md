# Task Context Template

Copy this file for one issued development task. Do not hand an agent the whole
context package.

## Task

**ID:**  
**Title:**  
**Status:**  

## Objective

State one coherent, independently verifiable change.

## Business purpose

Explain why the change exists and which user or business outcome it supports.

## Related requirements

List approved requirement identifiers only.

## Relevant architecture

List approved modules, decisions, interfaces, and data ownership rules only.

## Existing repository context

Name the current files, behaviour, and constraints the implementer must
understand.

## Inputs

List contracts, schemas, configuration, fixtures, or prior task outputs.

## Expected outputs

List changed or created artefacts.

## Implementation constraints

State architecture decisions that must survive implementation. Write `none
approved` rather than inventing them.

## Acceptance criteria

Use observable success, failure, and boundary conditions.

## Required tests

State test level, scenarios, and required evidence.

## Allowed file scope

List the exact files or directories the agent may change.

## Prohibited changes

Name adjacent work that must not be performed.

## Open issues

Carry unresolved questions relevant to this task. The agent must not silently
decide them.

## Definition of completion

State the code, tests, documentation, review evidence, and model updates required
for the task to be complete.

## Deviation report

When implementation reveals a conflict, classify it as:

- specification error;
- specification gap;
- implementation error;
- scope violation;
- discovery;
- constraint violation.

Stop expanding scope. Record the deviation and return it for a human decision.
